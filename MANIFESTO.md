# The Open Tools Doctrine

**Separate the tool from the performance. Open the tool to everyone. Charge only for the performance.**

This is the answer. Here is why it works, and here is how to act on it.

---

## The answer, in one sentence

**Tools are free and open to all. Performance — the doing, the using of tools to create value — is what people pay for.**

---

## Why the current world fails

- **Open projects die.** They fail when the *tool* and the *use of the tool* are fused into one thing. Users take the value for free, nobody pays for it, the makers burn out, the project starves.
- **Monopolies form.** Whoever owns a *closed* tool owns everyone who needs it. Innovation slows. The tool owner extracts value; the doers are locked in.
- **Value goes to ownership, not doing.** The person who owns the tool captures the worth that the creators actually produced.

## The three laws that fix it

**Law 1 — The Separation Law (how to find tools).**
> Remove it and the performance degrades; add it and the performance evolves.

That is how you detect a *tool* in anything: it is whatever is additive and removable — a reusable enabler. The thing it enables, the doing, is the *performance*. Probe any system this way and the tools separate themselves from the performances.

**Law 2 — The Layer Principle (why nothing can be monopolized).**
> The libraries that build MySQL are tools *to* MySQL. MySQL is a tool *to* developers. The next tool is the *schema*.

Everything is layered. Every tool is itself built of tools, and is itself a tool to the layer above. Because *every* layer can be opened, **no single owner can ever control the whole stack.** When a tool has mixed concerns, separate them — each separated concern becomes its own open layer, attachable and detachable on demand.

**Law 3 — The Incentive Model (why it stays alive).**
> Performance is paid, so performers fund the tools. If *they* don't, someone else will.

Better tools → better performance → more income. Every performer therefore has a built-in reason to improve the shared tools. Free-riding is impossible to end-run: if one performer won't pay, the one beside them will. The tool evolves no matter what, monopolies cannot form, and projects stay alive *because* value flows to the doing.

---

## What this changes

- **Monopoly becomes impossible.** Anyone can build with the open tools and supply what they enable. No lock-in, no tollbooths.
- **Copyright and patents stop gating knowledge.** Anyone can learn how to make the DNA, the database, anything. Only *performance* is sold.
- **Societies that win by owning tools lose that edge** and must instead win by performing. The rival advantage shifts from *having the tool* to *doing with it*.
- **Human advancement accelerates.** Knowledge diffuses freely; effort goes into doing; the shared tool pool rises for everyone.

---

## How to act on it (for whoever reads this)

1. **If you build a tool, open it.** Give it a permissive open license. Let everyone use it.
2. **Sell the performance, not the tool.** Charge for the product you make, the service you provide, the using of the tool — not for access to the tool itself.
3. **Improve the tools you depend on.** It is your own business to, because your performance rides on them.
4. **Spot the next layer.** Ask always: what repeated pattern do performances keep following? Separate it, open it, repeat.
