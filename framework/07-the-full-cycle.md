# The Full Cycle — The Doctrine as One Continuous Loop

Every other document in this repo is one piece of the doctrine viewed in isolation. This document
traces the pieces as they actually connect: a single, self-sustaining loop that runs from spotting a
hidden tool, through opening it, to the economy compounding on top of it — and then repeats forever.

Read this if you want the whole argument in one pass. The numbered steps draw only on the source of
truth (`raw/VERBATIM-RAW.md`); each step names the piece of the doctrine it uses.

---

## The loop at a glance

```
 1. SPOT      find the repeated pattern           (the Separation Law)
 2. SEPARATE  detach it from the performances     (mixed concerns, attach/detach)
 3. OPEN      release it free to everyone         (no copyright/patent; no monopoly)
 4. PERFORM   build value on top of it            (the money gate)
 5. FUND      the earners improve the tool        (the incentive model)
 6. PUSH      the shared frontier outward         (diminishing returns as signal;
                                                  the externality chain)
 7. VALUE     the ones who build it value it      (the missing key — the path, not the tool)
       ↑                                     ↓
       └───────────── back to step 1: next layer, forever
```

The loop is closed and endless: solving one friction surfaces the next, so the whole cycle starts
again at a higher layer. That is why the doctrine never stalls.

### A note on scope: tools are not only software

Nearly every concrete example in this doctrine is software — MySQL, schemas, libraries — because the
author is a software developer. Do not mistake the examples for the claim. A tool is *anything* that
takes input and gives output and can be separated from the performance that uses it. The raw is
explicit that the span is total:

> "Anyone knows how to make DNA, how to make database, how to make anything, if we only separate the
> tool section from performance section."

The stone-and-wood example in the missing-key step is a physical tool; DNA is a biological one. The
layering, separation, and opening logic applies to every domain the same way.

## Step 1 — SPOT: find the repeated pattern (the Separation Law)

Everything begins with noticing that a performance keeps following the same shape. The raw words:

> "It's only a matter of asking ourselves: how to make a new tool by separating performance from the
> pattern that the performance follows repeatedly."

The **signal** of a hidden tool is recurrence. When the same doing — authentication, payment,
cataloging, user management, backup, notification — keeps repeating across actors and domains, there
is a tool folded inside it. The Separation Law turns that suspicion into a test:

> Remove it and the performance degrades; add it and the performance evolves.

A thing that behaves that way is a tool, and therefore a candidate to be separated and opened. See
`01-core-framework.md` for the full law.

## Step 2 — SEPARATE: detach it from the performances (mixed concerns)

A real tool is almost never found alone; it is bundled inside performances or fused into other tools.
The doctrine's rule:

> If the tool has mixed concerns, separate them.

Each separated concern becomes its own thing, and each can become its own layer. The operation that
makes this safe is **attach / detach on demand**: a performance that needs the concern folds it in and
gets its benefit; one that does not leaves it out and stays lean. The raw:

> The beauty of this work is different concerns can be attached or detached from the last tool layer
> on demand. This makes the separation that just works.

See `02-layer-model.md` and `03-separation-methodology.md` for the layering and the fused-concern case.

## Step 3 — OPEN: release it free to everyone (no monopoly)

The separated tool is released open and free. The raw is explicit about what this removes:

> There would not be any copyright or patent rights — those suddenly become unusable. Anyone knows how
> to make DNA, how to make database, how to make anything, if we only separate the tool section from
> performance section.

Opening the tool is what makes monopoly impossible: with the tool in everyone's hands, anyone can
supply whatever it enables, so no single owner can hold a tollbooth. Because every layer can be
opened, **no single owner can ever control the whole stack** (the Layer Principle). See
`02-layer-model.md`.

## Step 4 — PERFORM: build value on top of it (the money gate)

The tool is free; the **doing** is what is paid for. Those who use the open tool to create value earn
from the performance, not from owning the tool. This is the separation of concerns made concrete:

> We should separate tools from performance and expose tools for all people, keeping performance as
> the money gate.

A reader sometimes pauses here and asks: *"if the tool is free and anyone can use it, why would anyone
pay at all?"* The separation is the answer. A free tool is a free *input* — it makes the doing cheaper
and open, but it does not do the doing. The **done thing** — the product, the service, the delivered
work — is still produced by a performer's time, skill, and judgment, and that is what is bought. Free
tools lower the cost and widen who can compete, but performance still has to be performed, and
performing is what someone pays for. Nothing about "tools are free" makes the doing free.

## Step 5 — FUND: the earners improve the tool (the incentive model)

Now the natural incentive kicks in. A performer's income depends on the quality of the tools they
perform with. So:

> Those who gain profit from performing using those tools automatically have the interest to spend for
> making the tool advanced.

And the structural guarantee that this holds even against free-riders:

> If they don't, others will.

Because the tool is open and many performers depend on it, at least one of them will fund its
improvement — the tool evolves regardless of any single actor. See `04-game-theory.md`.

## Step 6 — PUSH: the shared frontier outward (diminishing returns as signal; externality chain)

Improving a low layer lifts everything above it without touching them, because **tools are made from
other tools**:

> If someone else makes the read lib of MySQL better, the whole chain gets benefit from it — so this
> has a big amount of externality.

And the growth does not stop at diminishing returns, because diminishing returns is not a wall but a
signal:

> The whole reason that lets R and D enhance the diminishing law is that technology solves a friction
> — and if tools be open and we solve the frictions on tools, it can make a cycle where diminishing
> return becomes some signal for finding the frictions, not the frontier that people think they cannot
> cross.

Each solved friction makes use cheaper, usage rises, and a *new* friction surfaces to be solved next.
See `05-macro-economics.md`.

## Step 7 — VALUE: the ones who build it value it (the missing key)

The loop would break if the "open" step meant *handing finished tools to people who did not earn them*
— because people mis-value what they did not build. The raw:

> Those people have to make it themselves. Unless they are not going to realize the price it took until
> having that tool, and they won't value it correctly.

So the open step is completed by giving the **path**, not just the tool:

> Provide the way how a tool will be made using the specific limitations that those societies face.

The society builds it → values it → the chain starts → it passes the limit → next year a more advanced
tool → growth → and then it pushes the frontier itself. This is what lets a society enter and then
*contribute* to step 6, keeping the loop honest. See `06-missing-key.md`.

### Resolving the apparent conflict: "free tools" vs "they must build it themselves"

A careful reader will notice the doctrine says two things that seem to disagree:

- Step 3 says tools are opened **free to everyone**.
- Step 7 says people **must make the tool themselves** or they won't value it.

These are not in conflict because they describe **two different recipients in two different
situations**:

- The performer at step 4 is **already building** — they are actively creating value with tools. For
  them, the tool arrives open and free, and that is correct: they are already doing, so they already
  internalize the tool's value through the performance it enables. Handing them a finished open tool
  does not mislead them; it accelerates what they are already doing.
- The **underdeveloped society** in the missing-key step is **not yet building** — and it is the one
  the *finished, foreign* tool is the danger for. Feed a finished tool to a society that has not yet
  paid the price of building, and it will not realize the cost and will misuse the tool.

So the rule is precise: **open the tool freely to those who are already performing, and give the path
to those who have not yet built.** Both get tools for free; only the second gets the *path* as well,
because only the second still needs to learn the value by making it. There is one doctrine, not two.

And the loop's **on-ramp** is not a fragile edge case: every real society already stands inside the
world's pushed frontier and already receives its externality, so the chain is a humanity-level
compounding engine, not a lone-subsistence ladder (see the on-ramp section in `06-missing-key.md`).

## Why the loop is closed

Three properties make the cycle self-sustaining rather than one-shot:

1. **Frictions are produced by higher usage.** Every time the biggest friction is solved, usage rises
   and a new, previously-not-biggest friction surfaces. Growth therefore generates its own next
   problem to solve — the cycle never runs out of work.
2. **Every tool is a layer in a stack.** Nothing sits outside the stack, so there is always a "next
   tool" — the schema above the database, the recipe above the model — ready to be spotted, separated,
   and opened.
3. **Value flows to the doing.** Because performance is the money gate and tools are shared, the people
   with the strongest interest in better tools are exactly the people able to fund them. The fuel for
   the cycle comes from inside the cycle.

## What would break the loop (and what prevents it)

| Failure | How the doctrine prevents it |
|---|---|
| Tools never get funded (open = free = starved) | Performance is paid; earners fund the tools they depend on ("if they don't, others will") |
| A monopoly captures a layer | Every layer can be opened; a closed tradable tool collapses the moment it is seen and improved |
| People get free tools and mis-value them | Give the path, not the tool — they build it and value it correctly |
| Diminishing returns stalls growth | It is a signal for the next friction, not a wall; solved frictions surface endless new work |
| A society cannot enter the chain at all | Every real society already receives the world's pushed frontier; helping it returns surplus to its own frontier push |

With all five prevented, the loop is closed and compounding forever. Our only responsibility, per the
raw, is to let people know it is possible.

> **The one-line version:** *Spot the repeated pattern, separate it from the performance, open it to
> everyone, perform on top of it, let the earners improve it, let that improvement push the shared
> frontier — and give each society the path to build its own tools so it values them and joins the
> push. Then repeat forever at the next layer.*
