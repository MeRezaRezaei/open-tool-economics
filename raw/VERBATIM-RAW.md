## Core Thesis

We should separate tools from performance and expose tools for all people, keeping performance as the money gate. Those who gain profit from performing using those tools automatically have the interest to spend for making the tool advanced. This creates a game where the performers act for others' right of having better tools too.

## The Open Source License Advantage

If the tool has an open source license, this prevents monopoly and keeps economy gain benefit at performing instead of making special close tools that take others from getting the externality of advanced tools.

## Why Open Source Projects Die

Open source projects that no longer exist actually only died because they attached the concern of tools to the concern of using the tool (performance). People get externality from the tools that are out there only by learning how to use it, and that makes sure they get back to make the tool advanced — since if they don't, others will.

## The Monopoly Solution

Any long term monopoly would be impossible. It makes the most value ever even with lowest price, since having tools in the hands of anyone lets anyone supply the goods that the tool can provide. The supply increases on demand. This means the tool value is not compared to money — value increases even if you never trade the tool that lets you know its price.

## Beating Closed Source

This can beat other tools that are not open source to lose value without realizing. This makes the most valuable things humans have, since it is the main source of solving monopoly, at the same time keeps cash flow and contribution still that lets the tool evolve faster by automatically observing the value in supply chain without having to be worried about the supply chain.

## The Idea (Not the Tools)

The idea of having tools open source and free and the result of tools being sold. This shifts the monopoly. A lot of advanced societies lose their advantage and get forced to help making the tools better. The rival shifts from having advantage in tool to having advantage in performance, and lets human societies advance faster.

## No Copyright or Patent

There would not be any copyright or patent rights — those suddenly become unusable. Anyone knows how to make DNA, how to make database, how to make anything, if we only separate the tool section from performance section.

## The Layer Separation Problem

But solving the issue needs some more steps. There are a lot of performance that are dependent on tools that are integrated into performance. The question is: how to separate those?

The matter is how to decrease the tool as a tool to usage. If we decrease the tool from performance, the performance also degrades. But if we add tool, the performance evolves. So we can use this law to be able to spot what is tool and what is performance.

## The Layer Model

It's a matter of layers — just like the libs that are making the MySQL are the tools to MySQL, but MySQL itself is a tool to developers. And the next tool in the database problem that is not open source but can be a tool to is the schema of the database.

In this industry, making schemas open source makes the tools another layer to become open source.

## Mixed Concerns

If the tool has mixed concerns, we should separate them. This lets the tool become separated from performance. You make for MySQL some tools that make ready schema for some pattern that repeats, like predefined user management schema as a tool.

The beauty of this work is different concerns can be attached or detached from the last tool layer on demand. This makes the separation that just works.

## The Formula

It's only a matter of asking ourselves: how to make a new tool by separating performance from the pattern that the performance follows repeatedly? This becomes the exact new layer of tool one must make to push this work further.

## The Poverty Trap

When you make tools free, it cuts the prices of things. That is the same reason it breaks the poverty trap. Poverty is a combination of problems, and the one that makes long-term established monopoly is having better tools. So if the tool part gets solved, it breaks the chain of the world poverty trap — for all nations, not only one of them.

## Tool Neutrality

The tool is not dependent on the way you use it. A knife can be used for murdering or surgery. No one can say "we should not make tools" — it is the action that people do using the tools that has consequences, not the tool itself. So it won't break social law or life.

## The GNU/Linux Lesson

I made a big attention to find the answer for the question of why the GNU/Linux open source free copyleft idea worked best at start and then it became something that stucked in diminishing return law. This gave me the idea to separate them. People make tools and performance together, since if they are not together it is not usable and nobody pays for it, so they have to mix — the exact concern I am trying to separate, which is tool from using the tool. You can spot this pattern inside the open source world: whenever the using side gets ahead of quality of tool, the project gets into diminishing return trap.

## What We Have More Than Open Source Ideology

The exact point is how to spot something is tool and something is usage of tool, then make the tool better — it makes all underlying better. Continuing this makes more opportunities for finding out more better tools, and this cycle continues forever. Just like in the MySQL example: someone figures out a way to make a new tool that uses MySQL with some real world scenario for managing users permissions etc. The core difference for the operation that makes a tool better comes from the moment it is usable — then changes will make a staging state when it is not usable, until it becomes usable again, that makes a better result. Just like keeping concern of managing users as goal of tool and make a new tool that handles some concerns without the one who uses the tool needs to deal with its problems.

## The Absolute Definition of a Tool

The whole point of tool, the meaning of tool, comes from the fact that it is going to do something that the user is not going to necessarily know — it just takes some input and makes some output. Since we know the material for that tool as input and we expect the tool to give us the output, anyone can take these two things as the absolute definition for what the tool should do. Anyone can make things around it and in a big picture those are just some combinations. But the person who uses the tool to make a supply is the most probable person who can spot the tool flaw — no matter how the tool is integrated into a bigger system.

## The Friction Cycle

Any time we make some concerns separate from each other we make a trade off, and the trade off is always going to solve the biggest friction. But as the friction gets solved, usage will be increasing since it is now cheaper. This higher amount of usage makes some other friction points that were not the biggest friction at the time shift to become the next biggest friction. This process lets the thing to grow. The economy sticks at diminishing return because of a kind of friction — and solving the friction opens the border to higher level and next frictions to solve. The whole reason that lets R and D enhance the diminishing law is that technology solves a friction — and if tools be open and we solve the frictions on tools, it can make a cycle where diminishing return becomes some signal for finding the frictions, not the frontier that people think they cannot cross.

## Frictions Are Results of Higher Usage

The whole idea has built up on it that frictions are the results of higher usage of tools, and the only way that lets you never deal long term with diminishing return is to think of it before it comes.

## How This Evolves the Poverty Line

Tools are made from each other. If someone else makes the read lib of MySQL better, the whole chain gets benefit from it — so this has a big amount of externality. This means if somebody solves the MySQL lib, he is also letting the user manager tools to push the diminishing return frontier. And this lets economy grow faster than anyone can imagine. All of this happens by knowing the correlation of these works. The poverty line becomes even in long term just by using externality of free open source tools to indirectly push the diminishing return frontier.

## The Missing Key — The Path, Not Just the Tool

Only one piece of problem is missing and it is the key that lets the cycle complete. The idea of tools as the core for economic growth is not new. People have tested several things to societies that did not grow compared to the rest, and all of them failed. Here is the why and what to do.

For example, wealthy countries give free food to African underdeveloped societies and they end up with new babies and less food, because it is free. But why does it become something like this? Because using tools has some levels you cannot prevent, and even you should not prevent them unless you lose.

We are going to make the how to make that tool when you only have stone and wood manifest open source and free — but those people have to make it themselves. Unless they are not going to realize the price it took until having that tool, and they won't value it correctly. It is not a matter of right and wrong. It is a matter of correct value that lets people use the tool as its best suits.

So the answer to solving this problem is just to provide the way how a tool will be made using the specific limitations that those societies face. They definitely can make that, and start the chain effect I explained. The chain effect lets them pass the limitations away, and next year they will have the next complicated tool, and it continues until they would grow fast and they realize how it worked, and they start to help pushing the frontier of the diminishing law.

This is win-win, since no one in the world can control all tools, and anyone wants the next tool chain effect to happen. People won't get into conflicts that do not let others to have their tools, because the tool can cause them to lose what they worked for it — but the tool is free for everyone. And the society that you gave the path of having tools also won't benefit from keeping their tool development close, since others are doing a world class work to push those tools and push the frontier.

Choosing to make your own private tools only means in a matter of time others would grasp you and cause you a bankruptcy, and the risk is real. This is the game behind it that does not let the system break in long term. Because if the private tool you have as a monopolist, whose input and output is clear to the world — unless you cannot sell it, if it is tradable, its material is obvious — can suddenly collapse only when someone else sees it, and by having the rest of the information about the tools, they make the improvement that your monopoly advantage collapses overnight because of this.

This is the path that makes the game and puzzle complete. So the poverty trap, which is the reason for societies stopping from growing, would be solved. And our only responsibility is to let people know how it is possible.

## On The On-Ramp (Not the Jungle Case)

It is not the case that a society in the Amazon jungle that had no interaction with others is failing to enter. The current societies in any part of the world get externalities from the rest of the world — from the frontier that is being pushed. In fact, the big societies have an interest to give others those paths and tools, since currently they are the only ones that make externality. After the change, they can use the surplus of others, in the form of free open source tools, to push their frontier too — since the diminishing law frontier is a problem at the humanity level, not special people. And after all, limitations are real: for having double the speed for pushing the frontier in 40 years, it is better to develop those societies so they can double the force and make the frontier get pushed in 30 years for everyone in the world.
