# Verbatim: The Economics of Open Tools

## Core Thesis

We should separate tools from performance and expose tools for all people, keeping performance as the money gate. Those who gain profit from performing using those tools automatically have the interest to spend for making the tool advanced. This creates a game where the performers act for others' right of having better tools too.

## The Open Source License Advantage

If the tool has an open source license, this prevents monopoly and keeps economy gain benefit at performing instead of making special close tools that take others from getting the externality of advanced tools.

## Why Open Source Projects Die

Open source projects that no longer exist actually only died because they attached the concern of tools to the concern of using the tool (performance). People get externality from the tools that is out there only by learning how to use it and makes sure they get back to make the tool advanced - since if they don't, others will.

## The Monopoly Solution

Any long term monopoly would be impossible. It makes the most value ever even with lowest price since having tools in hands of anyone lets anyone supply the goods that tool can provide. The supply increases on demand. This means the tool value is not compared to money - value increases even if you never trade the tool that lets you know its price.

## Beating Closed Source

This can beat other tools that are not open source to lose value without realizing. This makes the most valuable things humans have since it is the main source of solving monopoly at the same time keeps cash flow and contribution still that lets the tool evolve faster by automatically observing the value in supply chain without having to be worried about the supply chain.

## The Idea (Not the Tools)

The idea of having tools open source and free and the result of tools being sold. This shifts the monopoly. A lot of advanced societies lose their advantage and get forced to help making the tools better. The rival shifts from having advantage in tool to having advantage in performance and lets human societies advance faster.

## No Copyright or Patent

There would not be any copyright or patent rights - those suddenly become unusable. Anyone knows how to make DNA, how to make database, how to make anything if we only separate the tool section from performance section.

## The Layer Separation Problem

But solving the issue needs some more steps. There are a lot of performance that are dependent on tools that are integrated into performance. The question is: how to separate those?

The matter is how to decrease the tool as a tool to usage. If we decrease the tool from performance, the performance also degrades. But if we add tool, the performance evolves. So we can use this law to be able to spot what is tool and what is performance.

## The Layer Model

It's a matter of layers - just like the libs that are making the MySQL are the tools to MySQL, but MySQL itself is a tool to developers. And the next tool in database problem that is not open source but can be a tool to is the schema of the database.

In this industry, making schemas open source makes the tools another layer to become open source.

## Mixed Concerns

If the tool has mixed concerns, we should separate them. This lets the tool become separated from performance. You make MySQL some tools that make ready schema for some pattern that repeats, like predefined user management schema as a tool.

The beauty of this work is different concerns can be attached or detached from the last tool layer on demand. This makes the separation that just works.

## The Formula

It's only a matter of asking ourselves: how to make a new tool by separating performance from the pattern that the performance follows repeatedly? This becomes the exact new layer of tool one must make to push this work further.
